# AI 桿弟：設計文件

最後更新：2026-11-22。這份文件記錄 AI 桿弟的目標、架構、已定案的決定和實作進度。整個專案是開源的，設計也放在這裡。

## 目標

站上發球台，或走到球旁邊時，問一句話，桿弟就依**我自己的歷史紀錄**回答這一洞怎麼打：

> 331 碼。一號木桿 170 碼，接鐵木桿 133 碼，順利的話直接上果嶺，不順利再用 A 杆切上去，兩推，5 桿 Bogey。

重點是給一條**完整的路線**（第一桿、第二桿、第三桿），而不只是「這一桿用哪支」。打完一桿、球落在別的地方，路線就從新的位置重算。

## 架構

```
手機：觸發與收音 ─┐            ┌─ 唸出回答
手機：定位 GPS ───┤            │
                  ▼            │
伺服器：語音辨識 → 理解問句 → 攻略引擎 → 組成回答
                                  ▲
資料（這個 repository）：各桿的分布、球洞輪廓、「還要幾桿」的表
```

- **攻略引擎**是唯一決定建議內容的地方，是純計算，同樣的輸入永遠得到同樣的答案，所以可以用歷史資料回測。
- **語言模型不參與選桿**，只幫忙理解問句（球位、風、距離）。回答用固定句型，要短。
- **語音只負責聽和說**，換觸發方式或換辨識服務都不影響建議。

## 攻略引擎

### 兩張表（`scripts/build_report.py` 的 `caddie_model()`）

1. **還要幾桿的表**：我每一筆擊球之前的位置（離旗桿幾碼、什麼球位）→ 那一洞從這一桿算起實際又用了幾桿。依距離分組取平均，再修成「離得越遠、桿數不會越少」。球位分球道、長草、發球台；沙坑樣本少，用「比長草多幾桿」一個數字；果嶺用平均推桿數。
2. **各桿的樣本**：每一筆擊球的起點距離、前進碼數、落點距離、落點球位、之後實際又用了幾桿。

### 一支桿的預期桿數（`DRAW.caddie` 的 `evalClub()`）

- 距離在這支桿打得到的範圍內：直接取我用這支桿、從相近距離（±25%）、同樣球位打過的那些球的實際結果。
- 超出範圍：取這支桿全揮桿的前進碼數，算出新的距離，再查第一張表。
- 預期桿數＝1＋這些結果的平均。附標準誤；兩支桿的差距小於誤差時，不說哪一支比較好。

### 路線（`route()`）

從球的位置開始，每一桿選預期桿數最低的球桿，照它的常態距離（中位數）前進，下一桿假設在球道，直到上果嶺，再加兩推。

- 「順利的話直接上果嶺」＝這支桿十球裡最遠的那一球到得了。
- 路線是「照常態打」的結果；另外列出「你從這裡平均幾桿」，通常比較多，因為會有打壞的球。
- 球袋和訓練計劃的選桿表一致：一號木桿（發球台、230 碼以上）、鐵木桿、6 鐵、8 鐵、P 杆、A 杆、54 度（沙坑）。

### 落點是一個區域，而且有分支

桿弟的目的是把整洞的揮桿路徑規劃清楚：每一桿可能落在哪個範圍、打得好接什麼、打不好接什麼。

- **落點畫成一個區域**，不是一個點。前後是這支桿十球有八球的距離；左右是「從球道中線附近打出去的球，落點偏離中線幾碼」的十球有八球範圍（`caddie_path()`、`_path_offset()`）。一號木桿 411 球：左 20 碼到右 30 碼，中位數偏右 7 碼；鐵木桿 316 球：左 18 到右 25，偏右 5 碼。所以右曲會讓整個區域偏右。
- **每一桿有兩個分支**：「打得好」＝十球裡第九遠的距離、下一桿在球道；「打不好」＝十球裡第二短的距離、下一桿在長草。各自寫出剩幾碼、接哪一支、照常態還要幾桿。

### 瞄準線沿著球道走

路線不是直接指向旗桿。把球道輪廓每 40 碼取一個中心點，從發球台連到旗桿，距離沿著這條線量，所以狗腿洞的碼數和落點都跟著球道轉彎。沿球道的長度比直線多 12% 以上時，視為輪廓辨識有誤，退回直線。球離這條線超過 30 碼（打歪了）時，改成直接指向旗桿。

發球台的位置取歷次開球起點的中位數；第一筆紀錄不一定是開球，所以只取離旗桿距離和中位數差不多的那一群。

### 目前沒有考慮的

依右曲調整瞄準點（目前只畫出偏右的落點區域，還沒有建議瞄左幾碼）、障礙物的罰桿（只列出位置）、風、高低差、這一洞自己的歷史。旗桿位置是上次打的那天的。

## 不用講話的用法：「我在這裡，怎麼打？」

桿弟頁最上面有一顆按鈕。走到球旁邊按一下：

1. 瀏覽器取得手機的 GPS 位置。
2. 找出你在哪個球場、哪一洞（離「發球台到旗桿」那條線最近的洞），換算成球洞圖上的位置。
3. 從那個位置算路線，顯示並用手機的語音唸出來。

其實上場要問的就只有「現在怎麼打」這一句，所以不必語音辨識，也不需要伺服器和金鑰，整件事在瀏覽器裡完成，位置不會傳到任何地方。

經緯度換成圖上座標的方法：`data/raw/gps/` 裡每一桿的起點、落點和旗桿都同時有經緯度和像素座標，對每一洞做最小平方法求一個仿射轉換（`caddie_geofit()`），目前 340 洞有轉換。只有打過的球場能用。

限制：球位是從輪廓猜的（長草、斜坡要手動改）；相鄰球道可能認錯洞，認錯時手動選洞再點圖。

## 模擬器

不上場就能測。選球場和洞，在圖上點一下當成球的位置，顯示桿弟會說的那句話、每一桿的路線和落點。整個引擎在瀏覽器裡跑，不需要伺服器。

第二階段會在同一頁加上錄音：座標用點出來的假位置，聲音是真的，送到伺服器走完整條管線，並顯示每一段花的時間。捷徑和模擬器呼叫同一個伺服器介面，所以在家測過的，上場只剩 GPS 和訊號兩個變數。

## 開源與金鑰

- 程式、資料、設計全部公開。
- 金鑰不屬於程式：只放在執行服務那台機器的 `.env`。`.env` 已列入 `.gitignore`，repository 裡只有 `.env.example`（欄位名稱）。
- 網站是靜態的，寫進網頁的東西任何人都看得到，所以**網頁裡永遠不放金鑰**。模擬器完全不需要金鑰。
- 之後的問答服務要帶一組存取密碼並限制頻率，避免別人消耗 API 額度。
- fork 這個專案的人自己準備 `.env`。

## 限制

- 每一洞只打過一到四次，建議主要來自各桿的分布，不是那一洞的歷史。
- 細分球位之後樣本更少（6 鐵只有二十幾球），頁面上每個數字都附球數和誤差。
- 球場輪廓是依地圖重新描的，個別洞的果嶺或沙坑可能沒抓到；球位判斷可以手動改。
- 沒打過的球場沒有輪廓，只能依距離和球位選桿。
- 正式比賽的規則不允許用裝置建議選桿。
